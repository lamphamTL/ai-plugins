Plan: Codex Credit Cycle Tracker

Issue source: lamphamTL/ai-plugins#9

Summary

Fix issue #9 by changing only Codex Weekly credits tracker from ISO Monday-Sunday week to Codex usage-cycle week: 7-day cycle starts at first Codex usage after previous cycle expires. Week charts stay calendar-based.

Key Changes

  • Add small pure Swift helper, likely CodexCreditCycle, used by UsageStore.buildDerived.
  • Replace weeklyCodexCredits ISO-week sum with current active Codex credit cycle.
  • Filter source == "codex" entries with non-nil credits, sorted by ts.
  • First cycle starts at first Codex usage.
  • If entry timestamp is >= cycleStart + 7 days, close old cycle and start new cycle at that entry timestamp.
  • Current tracker sum equals credits from latest cycle only, if Date() is before cycleStart + 7 days.
  • If latest known cycle already expired and no later usage exists, show 0 / 1000; next Codex use starts next cycle.
  • Expose richer state from store: used credits plus optional cycleStart/cycleEnd, so UI can show current cycle dates when active.
  • Keep existing 1000 credit limit and color thresholds unchanged.
  • Update token-usage-app/README.md to say Codex credit tracker uses first-usage-after-expiry cycles, not Monday-Sunday weeks.

Public Interfaces / Types

  • Replace or supplement UsageStore.weeklyCodexCredits: Double with codexCreditCycleUsed: Double.
  • Add optional codexCreditCycleStart: Date? and codexCreditCycleEnd: Date?.
  • UI label can remain Weekly credits; secondary text may show active cycle range when available, else Starts on next Codex use.

Test Plan

  • Add focused Swift unit-style test target or lightweight script test for pure helper.
  • Cover no Codex entries: 0 credits, no active cycle.
  • Cover entries within 7 days of first use: summed together.
  • Cover entry exactly at start + 7 days: new cycle.
  • Cover gap after expired cycle with no usage: 0 active credits.
  • Cover Sunday usage, then Wednesday usage after expired cycle: Wednesday becomes cycle start.
  • Cover Claude entries ignored.
  • Run cd token-usage-app && ./build.sh to verify app still compiles.

Assumptions

  • Scope is tracker only; Day/Week/Month chart bucketing remains calendar-based.
  • Cycle length is exactly 7 * 24 hours from first usage timestamp, not local midnight boundaries.
  • Existing historical log format stays unchanged; no migration needed.
