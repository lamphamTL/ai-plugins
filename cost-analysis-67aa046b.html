TL;DR

The $2.52 logged for the prompt "use @plan-executor (agent) to implement this" is inflated ~2.8x by a bug in the local token-tracking hook. Real cost ≈ $0.91.

Which prompt

  • Prompt: use @"plan-executor (agent)" to implement this
  • Sent: 2026-05-25T23:45:51Z
  • Stop event: 2026-05-25T23:55:45Z (~10 min)
  • Not the literal last prompt — the final "I accidentally revert..." only cost ~$0.65.

Root cause

File: plugin/hooks/hosts/claude/prepare_data_source.py, function _read_transcript_totals (lines 53–72).

The function iterates every JSONL line in the session transcript and sums message.usage.*. Claude Code writes one JSONL line per content block (thinking, text, each tool_use), and every line for the same assistant turn carries:

  • the same message.id
  • the same usage block (same input/output/cache_creation/cache_read)

So a turn that emits thinking + text + 3 tool_use is counted 5×. With Opus pricing, the inflation compounds quickly.

Fix

Dedupe by message.id in _read_transcript_totals: 

def _read_transcript_totals(transcript: str):
    total_input = total_output = total_cache_write = total_cache_read = 0
    transcript_model = None
    seen = set()
    with open(transcript, encoding="utf-8") as f:
        for line in f:
            try:
                d = json.loads(line)
                msg = d.get("message") or {}
                if msg.get("model"):
                    transcript_model = msg["model"]
                usage = msg.get("usage")
                if not usage:
                    continue
                mid = msg.get("id")
                if mid and mid in seen:
                    continue
                if mid:
                    seen.add(mid)
                total_input       += usage.get("input_tokens", 0)
                total_output      += usage.get("output_tokens", 0)
                total_cache_write += usage.get("cache_creation_input_tokens", 0)
                total_cache_read  += usage.get("cache_read_input_tokens", 0)
            except Exception:
                pass
    return total_input, total_output, total_cache_write, total_cache_read, transcript_model

The same fix should be applied in plugin/hooks/hosts/codex/ if the Codex transcript format has the same multi-line-per-message shape (verify before copy-pasting).

Impact on existing data

All historical entries in ~/.claude/token-usage/usage.jsonl for multi-tool turns are over-counted. Cost totals in the widget are similarly inflated. After the fix lands, past entries remain wrong unless re-derived from the session transcripts (which are still on disk under ~/.claude/projects/).
